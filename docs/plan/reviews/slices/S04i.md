## security (coordinator's security-engineer review, 2026-11-21, at `4ee5b41`)

Review only; reproductions ran outside the repo with synthetic loaders and sentinel values. 12 findings: 0 critical, 0 high, 3 medium, 6 low, 3 info. The three medium findings break P3 or acceptance 5 and 6, so they are **MUST-FIX**.

**MUST-FIX (architect):**
1. **SEC-1, P3 bypass:** gates and the store scan only statements of natural-person entities. A personal code in an event's `data` (for example an insolvency administrator field) or in a company statement reaches `main.events` unscanned (reproduced). Fix: run `findPersonalCodes` over every string in `event.data` in `applyGates`, drop and count `personal_code`, and add the same scan to the store's `refuse()` as a second line. Decide with legal whether company free-text props (name, address) are scanned too (§4.4 says person props only).
2. **SEC-2, values in the sync report:** `gates.ts` spreads loader drops as-is (`{ ...d, rowRef }`) and copies `party.type` into `prop`; non-strict validation passes extra keys. A `value` key, or a type field holding free text, lands in `report_json` (reproduced), including for `live-no-store` sources. Fix: build each drop as `{ reason, prop, rowRef }`; `prop` must pass `isProp()` (else `unknown`); party type only from a known list (else `other`); strict schemas or use the parsed data; a sentinel test.
3. **SEC-3, lease lost during a long fetch:** the 60 s lease has no heartbeat during fetch and parse, and a `false` heartbeat is ignored, so a second sync started more than 60 s into a long download runs in parallel (reproduced with a scaled TTL: two overlapping `content` rows). Fix: heartbeat on a timer (TTL/3) from acquisition to release; on loss, roll back, skip the purge and end `partial` with `lease_lost`; re-check the lease inside the purge transaction. Acceptance 5 gets a long-fetch case.

**SHOULD-FIX:**
4. SEC-4: live-cache views share one holder per process and hold a write transaction across `await`; two concurrent views of one record corrupt each other's transaction (reproduced). Unique holder, gather records before `BEGIN`, roll back only its own transaction, mark the sync `failed` on error.
5. SEC-5: `isPrivateAddress` misses IPv6 transition forms (IPv4-mapped in hex, NAT64 `64:ff9b::/96`, 6to4, `fec0::/10`, `100::/64`, documentation ranges) and IPv4 special-use ranges. Use a byte-level classifier (`net.BlockList`), re-check embedded IPv4, and share it with the agent fetch path (§12).
6. SEC-6: a redirect from https to http is followed, and caller headers (API keys) are re-sent. Refuse the downgrade; drop credentials when the host changes.
7. SEC-7: the 60 s timeout is idle-only (a 1-byte-per-10 s drip ran 70 s) and `Retry-After` has no ceiling. Add a total deadline per source, a minimum rate, a `Retry-After` cap (for example 300 s) and the HTTP-date form.
8. SEC-8: the raw cache's `safe()` lets `.` and `..` through, so a source id of `..` deletes the data dir (reproduced). Enforce `^[a-z0-9][a-z0-9-]{1,63}$` for `meta.id` in the registry invariants and assert containment before any `rmSync`.
9. SEC-9: the default 2 GiB size cap is buffered in memory (about 2x peak), and `gunzipSync` in the raw cache has no `maxOutputLength`. Per-source `maxBytes` with a lower default, stream large bodies to a temp file, cap decompression, and add "decompressed size cap" to the loader contract.

**NIT / notes:**
10. SEC-10: `bump()` loses a count keyed `__proto__`; use `Object.create(null)` or a `Map`, and make `reason` an enum.
11. SEC-11 (for S04f): the worker imports whatever module URL `workerData` carries. When the CLI or scheduler wires it up, pass a `sourceId` resolved against `LOADERS` inside the worker.
12. SEC-12: `live-no-store` views kept in worker module memory vanish with the worker (functional bug); a crashed worker leaves its `syncs` row `running`; raw cache and data dir use default permissions.

**Sound:** DNS pinning (every address checked, connection pinned including happy eyeballs, each redirect re-resolved, `file:` refused, exact official-host match); CRLF header injection rejected; size cap enforced on the streamed body with `identity` encoding; all SQL values bound, no identifier from source data; logs carry counts and error names only; `live-no-store` writes no raw cache, hash or rows; history excludes natural persons and `Person` rows; lease acquisition atomic; migrations lock and re-read the version.

**Not checked:** the suite in the reviewer's worktree (install not refreshed); real loaders and parsers (none yet: XML entity expansion, `__proto__` keys and regex DoS are reviewed per loader slice); `pnpm audit` for the new `zod` dependency; POSIX permissions beyond reading.

**Loader contract (data seats):** drops and report entries are built field by field from enums and ids; every loader that unpacks an archive caps its decompressed size; parsers are reviewed for entity expansion and prototype keys in each loader slice.
