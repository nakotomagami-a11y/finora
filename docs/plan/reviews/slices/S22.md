## Security review (coordinator's security-engineer, 2026-11-21, range `0919daa^..93cadeb` plus `57d7f1b`; S06 and S22 together)

Review only. Reproductions ran outside the repo. Threat model: a compromised or misbehaving allowlisted upstream, or a hostile web page in the user's browser. Assets: the server's uptime, the user's quotas, and listed persons' names. 10 findings: 0 critical, 0 high, 3 medium, 5 low, 2 info.

**MUST-FIX:**
1. **SEC-1, an XLSX cell or row reference kills the process with an out-of-memory error** (`packages/formats/src/xlsx.ts`, `readXlsx` and `readXlsxSheet`). Column and row numbers have no upper bound, so a 578-byte archive with one row at `r="300000000"` aborts with a fatal heap error. A fatal abort is not an exception, so no try/catch helps. An OOM in a worker without `resourceLimits` also kills the parent. It hits the markets gold sheet, which runs on the server thread, and `lv-fid-frozen`. **Fix:** throw `ArchiveError` past column XFD (16383) or row 1,048,576, and cap how far a cell or row may jump past the current length (for example 1,000). (Owner: data-osint, author of the readers.)
2. **SEC-2, quadratic regex scans in the XML helpers** (`formats/src/xml.ts`: `elements` with an opening tag that has no `>`; `withoutComments` with an unterminated comment; the copy in `sources/src/intl/sanctions/ofac.ts`). 40,000 repetitions (200 KB) take 9 s; a 20 MB member would take hours. The sync ends `worker_hung`, and on the markets path the event loop blocks. **Fix:** scan with `indexOf`. A comment with no end throws (truncated). `elements` scans to the closing `>` honouring quotes and stops when there is none. Remove the OFAC copy. (Owner: data-osint.)
3. **SEC-3, `uk-sanctions-list` stores an individual's name as an organisation alias** (`sources/src/intl/sanctions/uk.ts`, about line 138). It classifies a `Unique ID` group by its first row, the case S06's S2 fixed for `eu-fsf` only. Reproduced: an Entity row followed by an Individual row indexes 0 persons and stores the person's name as an alias, which the ungated `screenName` can then return. This breaks LAW-SANCTIONS-PERSONS. **Fix:** mirror `eu-fsf`: any individual row sends the entry to the person index, and mixed types are dropped as `unknown_subject_type`. Add the two-row test. (Owner: data-osint.)

**SHOULD-FIX:**
4. SEC-4: `esma` stores a row's name with no natural-person check (`intl/sanctions/esma.ts`). Keep a row only with a valid LEI or when `namesCompany(name)` passes; otherwise drop it as `unproven_party`. (data-osint)
5. SEC-5: a future-dated as-of from upstream freezes a market series for good, because every later run is `stale_skipped`, and a future `observedAt` never expires. Fail the sync as `as_of_missing` or `schema_changed` when the as-of or `observedAt` is more than a day ahead of `now`. (data-markets)
6. SEC-6: one huge CSV row takes about 2.7 GB of RSS before failing (`formats/src/csv.ts`). Cap fields per row (for example 1,000) and field length, and throw `CsvError` past either. (data-osint)
7. SEC-7: a failed market job tick is an unhandled rejection and leaves its sync row `running` (`apps/server/src/markets/jobs.ts`, `runner.ts`). Wrap each source run in try/catch, finish the sync as `failed`, and log `error.name` only. (data-markets)
8. SEC-8: a cross-site GET to `/api/v1/markets/crash` (an `<img>` tag or a no-cors fetch) passes the Host guard. It cannot read the answer, but it starts the jobs and switches interval jobs to their connected cadence. Mark a client poll only for `sec-fetch-site` `same-origin` or `none` (or absent), and start the jobs at boot (S25). Under H5 no keyed quota is involved, but outbound traffic is. (data-markets)
9. Defence in depth for SEC-1 and SEC-6: give sync workers `resourceLimits` (architect), and move market parsing off the server thread (data-markets, with S25).

**NIT:**
- SEC-9: the sheet name is decoded twice (`xlsx.ts:46`).
- SEC-10: a duplicate zip member name lets the last member win silently. `readXlsxSheet` calls `readZip` twice, so its real total limit is 40 + 20 MB. Throw on a duplicate wanted name, and carry the running total across both calls.

**Sound:**
- XML: no entity expansion, and DOCTYPE is never interpreted.
- XLSX shared-string indexes are safe, including NaN, negative and `__proto__` indexes.
- No prototype-pollution route: `Map`s and constant keys throughout.
- Zip64 fails closed; overlapping members are each counted; sizes come from the central directory, with the inflate cap and CRC.
- Keys never reach messages, reports, artifacts, hashes or the response; a header key is dropped when a redirect changes host; https-to-http is refused.
- The crash route goes through the guard, and its error path says only `internal_error`.
- JSON-RPC: never redirected, a 32 MB cap, block hashes validated, BigInt maths bounded.
- The person index is memory-only. `screenName` never reads it, and officer screening sits behind `purposedNames`.
- `lv-fid-frozen` needs a legal form for an unproven name.

**Not checked:** `pnpm audit` and semgrep; how the web UI renders stored `sourceUrl` or `website` values (S08: a `javascript:` link must be refused); real upstream bytes; the `screen_sanctions` API and MCP surface (S07 and S19); person-index speed on large buckets.
