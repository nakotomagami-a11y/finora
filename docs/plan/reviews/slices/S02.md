| # | Severity | Finding | Fix | Test | Status |
|---|---|---|---|---|---|
| SEC-1 | **MUST-FIX** | **Pages with a dot in the path skip `proxy.ts`**, so they get neither the Host check nor the CSP (`apps/web/src/proxy.ts:34`, matcher `"/((?!_next/\|favicon.ico\|.*\..*).*)"`; confirmed with Next 16.4.6's own matcher compiler: skipped for `/en/x.y`, `/x.y`, `/en/terms.rsc`, `/api/v1/health.json`). Catch-all and later dynamic segments (an id or name with a dot) would render without the DNS-rebinding guard, against the §12 rule of a check on every request. API routes stay protected because `handle()` guards again; their responses lose the headers | run the proxy on everything except `_next/static` (or drop the matcher); for `/_next/` and file-like paths, return the guarded response with headers and skip next-intl | e2e: `GET /en/x.y` with `Host: evil.example` → 403; with a normal Host the CSP carries a nonce; a unit test runs the matcher against a path table | open (frontend) |
| SEC-2 | SHOULD-FIX | `NODE_ENV` defaults to `development` (`apps/server/src/env.ts:8`), which turns on the weak dev CSP (`'unsafe-eval'`, inline styles, `ws:`) if unset in production | default to `production`, or key the dev CSP off the build-time `process.env.NODE_ENV` | `loadEnv({})` gives `production` | open |
| SEC-3 | SHOULD-FIX | The bundle check's `NEXT_PUBLIC_` case can't fire on a real build (Next inlines the value; CI sets no `NEXT_PUBLIC_*` sentinels), and the scan covers only `.next/static`, not `.next/server/app/**/*.{html,rsc}` | set `NEXT_PUBLIC_<NAME>=<sentinel>` in the CI build env; scan `.next/server/app`; an e2e grep of responses for sentinels | a fixture client component reading the `NEXT_PUBLIC` variant fails the check | open |
| SEC-4 | SHOULD-FIX | GitHub Actions pinned by tag, not commit SHA (`.github/workflows/ci.yml:57-77`), incl. the third-party `pnpm/action-setup` | pin full SHAs; Dependabot or Renovate updates them | a CI lint refusing `uses:` without a SHA | open |

NIT: tighten the Host pattern to `^(localhost|127\.0\.0\.1|\[::1\])(:\d{1,5})?$` (`guard.ts:6-10`); also refuse unsafe methods with `Sec-Fetch-Site: cross-site` and no Origin (`guard.ts:28`); note or remove `style-src-attr 'unsafe-inline'` (`guard.ts:52`); restrict the footer source URL to `http(s)` (`env.ts:12`); `/_next/image` is covered by SEC-1's fix or `images.unoptimized`.

**Verified:** foreign Host → 403 on the API and on undotted pages (case-insensitive; trailing dot and expanded IPv6 refused; only `Host` is read, never `X-Forwarded-Host`); foreign, `null` or garbage Origin on unsafe methods → 403; per-request nonce passed to the render and checked in e2e; production CSP without `unsafe-inline`/`unsafe-eval` for scripts and no wildcards, with `frame-ancestors 'none'`, `object-src 'none'`, `nosniff`, `no-referrer`, `poweredByHeader` off; binds 127.0.0.1; invalid env throws naming each variable without values; 500s send only a code; locale redirects sanitised; no person endpoints; install scripts denied by default, `minimumReleaseAge` set, workflow permissions read-only.

**Not checked:** a live server or `next build`; whether `next start` exits when `register()` throws; whether Next serves `/x.rsc` to outside requests; the lockfile's transitive install-script surface beyond `pnpm audit`.
