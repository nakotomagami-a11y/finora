These are fixture views of the data layer, not the final screens, which S08 and S11 build.

**Built (U2 acceptance, by number):**
1. **Reducer** (`lib/investigation-reducer.ts`). It is pure: an applied id changes nothing, and a skipped id sets `gap`. A seeded property test runs 200 shuffles. Usage never goes through currency or float maths.
2. **Replay equals snapshot.** All 11 scenarios in `fixtures/agents/` replay to their snapshot. The snapshot is folded by separate code.
3. **Gap:** on a gap the hook refetches the snapshot, then resumes with no lost or doubled finding.
4. **SSE client** (`lib/sse.ts`):
   - `Last-Event-ID`, plus the query fallback;
   - backoff of 1-15 s with jitter;
   - 45 s of silence forces a reconnect;
   - "reconnecting" shows only after 3 s;
   - no retry on a 4xx.
   It has 19 tests on a fake clock.
5. **Usage as integers** (`lib/format.ts`): `formatTokens`, `usageShare` and `meterParts`, plus date and time formatters in i18n.
6. **56 UI fixtures** under `fixtures/ui/<screen>/<state>.json`. A test checks each one against:

7. **Fixture mode** (`lib/fixture-mode.ts`): server-only, demo-only. Without `FINORA_DEMO`, a real `start` answers 404 and ignores `?state=` (e2e).
8. **Single-character shortcuts.** They are ignored in editable fields, with modifiers, in dialogs and when switched off. `Ctrl/Cmd+K` always works.
9. **Plumbing:**

## Reviews

**legal (7091122056):** no open item. The fixtures hold only Example names and fixture ids, and the host refusal is the control legal asked for.

**designer (7091126911), against DESIGN.md §9.4:** integer usage, `meterParts`, held usage counted while running and the fixture state coverage all match. **One SHOULD: rounding direction** (`lib/format.ts` lines 12, 13 and 25). `formatTokens` and `usageShare` round down, which understates use. The rule is now in DESIGN.md §9.4 (`95947fa`, `577da92`):
1. Used and held amounts, and the estimate's typical and worst cases, round up (149,020 st reads "149.1k").
2. Amounts left round down.
3. Caps show as set.
4. Shares round up to a whole percent. Non-zero use below 1% reads "under 1%". 100% shows only when the cap is reached.
5. Meter widths use exact values.

Suggested shape: `formatTokens(locale, n, { direction })`, plus a "left" helper that rounds down. **It must land before S11.** The coordinator batches it with qa's findings into one frontend fix round, so frontend takes a single slot.

**cto (7091141764):** confirms that the rounding rule matches the estimate line's intent: the screen never understates use or overstates headroom. Two notes, for S11:
1. The sample estimate copy breaks rule 1: its typical case was rounded down. At about 153k typical, it reads "about 154k" at three figures or "about 160k" at two. Designer picks the precision, and frontend updates the sample and its baseline when S11 draws the line.
2. Rounding is for display only. The `usage` DTO stays in integer st. Caps, the plan-limit pause, C19's overage rule and the 100% check all read the exact integers. S11 test (frontend): a run at 99.6% of its cap shows "99%", and every cap and pause decision is computed from the exact integers.

**qa (7091146134): DO NOT ACCEPT yet. 1 MUST-FIX, 1 SHOULD-FIX, 1 NIT.** The H4 check over the 92 touched files finds 0 unresolved. The guard and a name scan over every fixture string find 0 hits. `fixture-mode.ts` validates names before any path join, so there is no traversal.
1. **MUST-FIX: an event that arrives during a gap refetch is lost for good.**
   - The reducer drops events while `gap` is true (`investigation-reducer.ts:123`).
   - The stream effect (`use-investigation.ts:84-98`) never reopens after the snapshot loads.
   - Probe: snapshot at 3, event 5 makes a gap, event 6 (`waiting`) arrives during the refetch, and the snapshot comes back at 5. Event 6 is gone and the page waits for ever.

   Fix: reopen the stream after every snapshot load, so the server replays from the snapshot's id (coordinator's preference), or buffer events above `lastEventId` during the gap and apply them afterwards.

   Same area: a failed gap refetch leaves `gap` true for good, so retry it with the stream's backoff.

   Tests:
   - the probe ends at 6 in `waiting`;
   - a refetch that fails once, then succeeds.
2. **SHOULD-FIX:** `sse.ts:146` resets the backoff on every successful connect, so a server that accepts and then closes at once gets a reconnect about every second. Reset only after the first event, or after the connection has stayed up a few seconds.
3. **NIT:** `sse.ts:140-144` returns on a non-OK answer without aborting. Call `controller.abort()` first.
