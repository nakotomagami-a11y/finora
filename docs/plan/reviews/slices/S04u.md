## Security review (coordinator's security-engineer, 2026-11-23, commits `79e3fc1`..`c6018fa`)

Review only. The probes ran outside the repo. Threat model: a hostile page in the same browser, a hostile or buggy local server or stream, or a crafted URL. Six findings: 1 medium, 4 low, 1 info.

**MUST-FIX:**
1. **SEC-1 (medium): the gap refetch can loop with no delay** (`use-investigation.ts:111-114, 132, 148`; `investigation-reducer.ts:113, 169`). Suppose an event names a run or question that the snapshot lacks. It sets `gap`, the refetch clears it, the stream reopens, and the server replays the same event. The retry counters reset on every cycle, so neither the backoff nor the 5-minute give-up ever applies. The page hammers the local server and never settles. A server bug that makes the snapshot lag the event log is enough to trigger it. **Fix:** count, at hook level, the gaps in a row that a snapshot did not cure, and reset the count only when an event applies after a reopen. Back off on the stream schedule and fail after 5 minutes. **Test:** a server that keeps replaying an uncured event.

**SHOULD-FIX:**
2. **SEC-2 (low): the stream parser's buffer has no limit** (`sse.ts:20-53, 129`). A 64 MiB probe with no newline grew the heap by about 446 MB. Each chunk re-arms the 45 s silence timer, so a trickle keeps the connection open indefinitely, and every push re-scans the whole buffer. **Fix:**
   - cap the line and the data size (for example 1 MiB), and abort when either is exceeded;
   - re-arm the silence timer only on a complete line;
   - scan from the last offset.
3. **SEC-3 (low): the status goes from `failed` back to `reconnecting`** (`sse.ts:142-145, 176`). The 3 s timer is not cleared on the 4xx path. **Fix:** clear it before `failed` and whenever `run()` returns.
4. **SEC-4 (low): an invalid `resetsAt` string crashes the render.** `formatTime` throws `RangeError`.
   - **Fix, frontend:** the i18n formatters return a fallback for an invalid date.
   - **Fix, architect (contract queue):** type `resetsAt` and `at` as ISO datetimes.
5. **SEC-5 (low): `..` as a path parameter leaves the intended route** (`api.ts:24`). `encodeURIComponent("..")` is `..`.
   - **Fix, frontend:** `buildUrl` refuses `.`, `..` and any value containing `/`.
   - **Fix, architect (contract queue):** id parameters get an id pattern.
6. **Not checked, test asked for (frontend):** if the page stays mounted when the investigation id changes, an old investigation's late snapshot could be applied to the new one. Reset the reducer and cancel the load on an id change, with a test.

**NIT:**
- SEC-6: the demo redirect puts an unchecked locale into the path (`design/page.tsx:16`). It isn't exploitable as shipped. Check `isLocale(locale)` before redirecting.

**Sound:**
- Fixture mode is off without `FINORA_DEMO`. It is read at runtime and checked in both pages and both readers, and the pages are dynamic.
- Fixture names cannot escape the folder.
- Fixture code is server-only.
- Reconnects are bounded at 15 s.
- Every event is schema-checked. Duplicate and lower ids do nothing.
- `Last-Event-ID` is always an integer.
- Every `api.ts` body is schema-checked, and credentials are sent same-origin only.
- No XSS sink is in scope.
- The formatters terminate.

**Not checked:**
- The server side (Host and Origin guard, the SSE endpoint), which belongs to S07 and S09a.
- A fresh client bundle.
- The dependency audit.

## Security re-check of `0a799d6` (coordinator's security-engineer, 2026-11-23)

**Closed:**

**SEC-2 partly closed:** the 1 MiB cap counts UTF-16 characters, not bytes. The rest of SEC-2 depends on NEW-2.

**SEC-1 is NOT closed.** Two medium findings were reproduced, and both are MUST-FIX:
1. **NEW-1: a snapshot older than the page restarts the no-delay loop** (`use-investigation.ts:28, 144`). If the snapshot's `lastEventId` is below the page's, the "cured" check passes at once and the count resets. Probe: snapshot at 3, stream events 4 and 6. Result: 40 snapshot fetches and 40 stream opens, with `attempt` at 0 and no "failed". **Fix:** reset the count only from a counter the reducer bumps when an event actually applies, compared against its value when the stream reopened. A stale snapshot counts as uncured.
2. **NEW-2: "failed" stops neither the requests nor the stream, and the page then reads "live"** (`use-investigation.ts:204`; `sse.ts:178, 209`). `streaming` ignores "failed", and any valid event resets the stream's `attempt`, duplicates and gap-causing events included. Probe: after the 5 minutes, 61 stream requests in the next 60 s, with the status reading "live". The same cause makes "a valid event followed by more than 1 MiB" loop at about 1 per second. **Fix:**
   - `streaming` stays false after the give-up;
   - only a manual refetch may replace "failed";
   - `sse.ts` resets `attempt` only when an event moves the cursor (`onEvent` returns whether it applied).

**SHOULD-FIX: NEW-3 (low).** The 3 s "reconnecting" timer in the hook (`use-investigation.ts:159`) can fire after "failed". Clear it before each failed dispatch.

**Tests:** 134 of 134 across `apps/web/src/lib` and `packages/i18n/src`. No leaks on unmount.
